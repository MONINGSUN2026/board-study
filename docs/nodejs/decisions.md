# Node.js 결정 기록

Node.js 학습 과정에서 내린 기술·구조·운영 결정을 기록한다.

## 기록 규칙

- 결정할 때의 문제와 선택지를 함께 기록한다.
- 선택한 이유와 예상되는 trade-off를 남긴다.
- 이후 결정이 바뀌면 기존 기록을 삭제하지 않고 변경 이유를 추가한다.

## 결정 목록

### D-001. 학습 단위는 브랜치로 분리한다

- 상태: 적용
- 결정: Node.js 학습은 `frame/nodejs` 브랜치에서 진행한다.
- 이유: 다른 스택의 구현과 변경 이력을 분리하고, 공통 자료는 `main`에서 재사용하기 위해서다.

### D-002. 런타임과 패키지 구성

- 상태: 예정
- 결정: Node.js 런타임 버전과 패키지 구성은 초기 환경 점검 후 결정한다.
- 이유: 학습 환경과 지원 범위를 먼저 확인한 뒤 의존성을 고정하기 위해서다.

### D-003. 웹 프레임워크

- 상태: 예정
- 결정: 기본 Node.js HTTP 서버를 먼저 확인한 후 웹 프레임워크 도입 여부를 결정한다.
- 이유: 프레임워크 사용 전에 Node.js의 요청·응답 흐름을 이해하기 위해서다.
