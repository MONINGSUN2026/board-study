# Node.js 학습 계획

이 문서는 게시판을 실제로 개발하기 위한 작업 목록이 아니라, 설계부터 배포까지의 전체 흐름을 이해하기 위한 학습 커리큘럼이다.
각 단계의 학습 목표와 이해 여부를 확인하기 위한 포인트만 기록한다.

## 학습 원칙

- 기능 구현보다 개발 흐름과 판단 근거를 우선한다.
- 각 단계에서 왜 해당 결정을 내렸는지 설명할 수 있어야 한다.
- 다음 단계로 넘어가기 전에 확인 포인트를 스스로 검토한다.
- 이 문서의 내용은 개발 산출물이나 제품 요구사항으로 취급하지 않는다.

## 1. 프로젝트 이해와 요구사항 분석

### 학습 목표

- 프로젝트 목적과 게시판 도메인의 범위를 이해한다.
- 사용자·관리자 관점의 주요 흐름을 구분한다.
- 기능 요구사항과 비기능 요구사항의 차이를 이해한다.

### 확인 포인트

- 게시글·댓글·회원·관리자의 관계를 설명할 수 있는가?
- 목록·상세·작성·수정·삭제 흐름을 구분할 수 있는가?
- 구현 범위와 학습을 위한 가정이 분리되어 있는가?

## 2. 도메인과 데이터 설계

### 학습 목표

- 게시판 도메인의 핵심 객체와 책임을 식별한다.
- 관계형 데이터와 문서형 데이터의 차이를 비교한다.
- 데이터 무결성, 식별자, 상태값, 생성·수정 시간을 설계 관점에서 이해한다.

### 확인 포인트

- 게시글과 댓글의 관계를 설명할 수 있는가?
- 사용자 권한과 작성자 검증 위치를 구분할 수 있는가?
- PostgreSQL과 MongoDB를 선택할 때의 기준을 설명할 수 있는가?

## 3. 애플리케이션 구조와 API 설계

### 학습 목표

- 요청이 라우팅·서비스·저장소를 거치는 흐름을 이해한다.
- HTTP 메서드와 상태 코드를 용도에 맞게 선택한다.
- API 입력·출력·오류 응답의 일관성이 왜 필요한지 이해한다.

### 확인 포인트

- 목록·상세·작성·수정·삭제 API의 책임을 구분할 수 있는가?
- 인증 실패와 권한 부족을 구분할 수 있는가?
- 도메인 규칙을 라우터에 직접 두지 않아야 하는 이유를 설명할 수 있는가?

## 4. Node.js 실행 구조와 프로젝트 구성

### 학습 목표

- Node.js 런타임과 브라우저 JavaScript의 차이를 이해한다.
- 모듈 시스템과 의존성 관리 흐름을 이해한다.
- 환경 변수와 실행 환경별 설정의 역할을 구분한다.

### 확인 포인트

- 프로세스, 이벤트 루프, 비동기 작업의 관계를 설명할 수 있는가?
- `package.json`과 lock 파일의 역할을 설명할 수 있는가?
- 개발·테스트·운영 환경의 설정을 분리해야 하는 이유를 이해하는가?

## 5. HTTP 서버와 웹 프레임워크

### 학습 목표

- 기본 HTTP 요청·응답 흐름을 이해한다.
- 웹 프레임워크가 제공하는 라우팅·미들웨어·오류 처리 기능을 이해한다.
- 프레임워크 사용이 생산성과 추상화에 미치는 영향을 비교한다.

### 확인 포인트

- 요청 수명 주기와 미들웨어 실행 순서를 설명할 수 있는가?
- 동기·비동기 오류가 처리되는 방식을 구분할 수 있는가?
- 프레임워크를 도입해도 Node.js 동작 원리를 설명할 수 있는가?

## 6. 데이터베이스 연동과 트랜잭션

### 학습 목표

- 애플리케이션과 데이터베이스 연결 흐름을 이해한다.
- 조회·등록·수정·삭제 작업의 일관성을 이해한다.
- 트랜잭션과 동시성 문제의 기본 개념을 익힌다.

### 확인 포인트

- 연결 정보와 비밀값을 코드에 직접 두지 않는 이유를 설명할 수 있는가?
- 실패한 저장 작업을 어떻게 처리할지 설명할 수 있는가?
- 데이터베이스 오류와 도메인 오류를 구분할 수 있는가?

## 7. 인증·인가와 보안

### 학습 목표

- 인증과 인가의 차이를 이해한다.
- 세션·토큰 기반 인증의 기본 흐름을 비교한다.
- 입력 검증, 비밀번호 보호, 민감 정보 관리의 필요성을 이해한다.

### 확인 포인트

- 비로그인·일반 사용자·관리자의 접근 범위를 구분할 수 있는가?
- 사용자 입력을 검증해야 하는 위치를 설명할 수 있는가?
- 인증 정보와 비밀 설정을 안전하게 관리하는 방법을 설명할 수 있는가?

## 8. 테스트와 품질 확인

### 학습 목표

- 단위·통합·API 테스트의 차이를 이해한다.
- 정상·오류·권한별 시나리오를 구성하는 방법을 익힌다.
- 테스트 결과를 통해 설계 문제를 발견하는 흐름을 이해한다.

### 확인 포인트

- 핵심 도메인 규칙을 어떤 수준에서 테스트할지 설명할 수 있는가?
- 데이터베이스를 사용하는 테스트의 격리 방법을 이해하는가?
- 테스트 실패 원인을 코드·환경·데이터 문제로 분류할 수 있는가?

## 9. 운영·관찰 가능성·장애 대응

### 학습 목표

- 로그·오류 추적·헬스 체크의 목적을 이해한다.
- 운영 환경에서 설정과 코드를 분리하는 방법을 이해한다.
- 장애 발생 시 원인 파악과 복구 흐름을 익힌다.

### 확인 포인트

- 요청을 추적할 수 있는 정보가 무엇인지 설명할 수 있는가?
- 사용자에게 보여줄 오류와 서버에 기록할 오류를 구분할 수 있는가?
- 데이터베이스 장애와 애플리케이션 장애의 대응 차이를 이해하는가?

## 10. 컨테이너·CI/CD·배포

### 학습 목표

- 빌드·테스트·패키징·배포의 전체 흐름을 이해한다.
- 컨테이너가 개발 환경과 운영 환경에 제공하는 이점을 이해한다.
- 배포 환경의 설정, 롤백, 데이터베이스 운영 위험을 이해한다.

### 확인 포인트

- 배포 전에 자동으로 확인해야 할 항목을 설명할 수 있는가?
- 애플리케이션과 데이터베이스를 함께 배포할 때의 위험을 이해하는가?
- 배포 실패 시 이전 버전으로 되돌리는 방법을 설명할 수 있는가?

## 11. 전체 흐름 회고

### 학습 목표

- 요구사항부터 배포까지 각 단계의 연결 관계를 설명한다.
- 기술 선택과 구조 결정의 근거를 되돌아본다.
- 다음 스택 학습에 재사용할 수 있는 원칙을 정리한다.

### 확인 포인트

- 하나의 기능이 요구사항·도메인·API·DB·테스트·배포에 어떻게 연결되는가?
- 가장 큰 시행착오와 그 원인을 설명할 수 있는가?
- 다른 프레임워크나 데이터베이스를 사용할 때 달라지는 부분과 유지되는 부분을 구분할 수 있는가?
