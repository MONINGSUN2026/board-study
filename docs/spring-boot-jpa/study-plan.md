# spring-boot-jpa — 학습 계획 (Study Plan)

실제 개발 산출물이 아니라, **설계부터 배포까지의 흐름을 배우기 위한 커리큘럼**이다.
개발 산출물에는 반영하지 않고, 학습 목표·확인 포인트만 담는다.

## 1. 학습 목표

- **AI를 활용한 API 개발**을 경험한다.
- Spring Boot + JPA로 서비스를 **설계 → 구현 → 빌드 → Docker 배포**까지 끝까지 흘러보며 전체 흐름을 체득한다.

## 2. 역할 구분 (사용자 / AI)

> 사용자는 **결정하고 이해하는 사람**, AI는 **초안을 만들고 실행하고 설명하는 사람**.

### 사용자(학습자) 영역
- 방향·요구사항 제시
- 의사결정 (기술·설계·API 구성의 최종 승인)
- 이해·학습 (확인 포인트를 스스로 설명)
- AI 산출물 검토·피드백
- 원격 권한 (push 승인, PR 생성, 원본 base 브랜치 생성)

### AI(보조자) 영역
- 초안·코드 생성 (문서, API 목록, 엔티티, 소스)
- 실행 (파일 생성/수정, 빌드, commit, docker)
- **설명·교육** (개념, 원리, 선택지의 장단점과 이유)
- 검증 (컴파일·테스트·체크리스트)

### 협업 흐름

```text
AI 초안·설명 제시 → 사용자 검토·결정 → AI 반영 → 확정
```

## 3. 학습 커리큘럼 (설계 → 배포 흐름)

| 단계 | 주제 | 배우는 것 |
| --- | --- | --- |
| 1 | 요구사항·범위 | 요구사항을 API 관점으로 해석 |
| 2 | API 목록 | 기능 → 엔드포인트 도출 |
| 3 | 환경·기술 결정 | JDK·프레임워크·DB 버전 선정 근거 |
| 4 | 기술 설계 | 도메인·API·보안·예외·페이지네이션 설계 |
| 5 | 공통 영역 | 응답 포맷·예외·BaseEntity |
| 6 | 인증/인가 | JWT·Spring Security 흐름 |
| 7 | 관리자 회원관리 | 권한 기반 관리 API |
| 8 | 게시판/게시물 | JPA 연관관계·CRUD·파일 |
| 9 | 사용자 게시판 | 홈·무한스크롤(Cursor)·검색 |
| 10 | 빌드·배포 | Docker 이미지·compose·검증 |

## 4. 단계별 학습 목표·확인 포인트

각 단계를 마치면 아래를 스스로 설명할 수 있어야 한다.

- **설계**: ERD·API 명세를 보고 "왜 이렇게 설계했는지" 설명
- **공통**: 공통 응답·전역 예외 처리의 흐름 설명
- **인증**: 세션 vs JWT 차이와 선택 이유, Security 필터 흐름
- **게시판**: JPA 연관관계 매핑, 영속성 전이, N+1 식별
- **사용자 게시판**: Offset vs Cursor 차이와 무한스크롤 구현
- **배포**: Docker 이미지 빌드, 컨테이너 네트워크, 헬스체크

## 5. 학습 산출물

- `decisions.md` — "왜 이 기술·설계를 선택했나"
- `learnings.md` — "배운 점·시행착오·트러블슈팅"

## 6. 진행 원칙

- 각 단계에서 **무엇을 배우려는지** 먼저 확인한 후 진행한다.
- 구현 중 발생한 궁금증·이슈는 `learnings.md`에 누적한다.
- 학습 목표는 기술 관련 내용만 다루고, 실제 개발 산출물에는 반영하지 않는다.
