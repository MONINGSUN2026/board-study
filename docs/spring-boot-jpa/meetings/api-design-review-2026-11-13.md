## 안건별 논의·변경

### 안건 1. Base URL

| 구분 | 내용 |
| --- | --- |
| 변경 전 | `/api/v1` |
| 결과 | `/api/boot-jpa/v1` |
| 변경 근거 | 학습 단위(스택) 구분 필요. MSA는 도메인 단위로 나누지만, 본 프로젝트는 스택 단위 학습이므로 단위명을 URL에 포함한다. |

### 안건 2. API 목록 단계에서 남길 정보

| 구분 | 내용 |
| --- | --- |
| 결과 | ① 필요한 API 명시적 목록화 ② API 공통 구조 정의 ③ 페이지네이션·정렬 규칙 ④ 권한 |
| 변경 | `api-list.md`에 요청/응답 컬럼, 공통 상태코드, 파라미터 규칙 상세 추가 |

### 안건 3. D/E 영역 분리

| 구분 | 내용 |
| --- | --- |
| 변경 전 | D 게시판·게시물 관리 / E 사용자 게시판 |
| 결과 | D/E 병합 → **게시판(board)** 하나 |
| 변경 근거 | "단건/변경 vs 다건/조회" 분리는 인위적. 실무에서 게시글 CRUD와 목록·검색은 같은 도메인이므로 병합한다. |

### 안건 4. API 분리 기준

| 구분 | 내용 |
| --- | --- |
| 결과 | 리소스(데이터) 단위로 분리, 권한은 리소스의 속성, 화면은 API 조합 |
| 변경 근거 | 화면 기준 분리는 중복·파편화 유발. 재활용 + 책임분리 원칙에 부합. |

### 안건 5. 인증 방식

| 구분 | 내용 |

| 변경 근거 | stateless, 서버는 서명 검증만 수행해 확장에 유리. |

| 구분 | 내용 |
