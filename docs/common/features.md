# 구현 기능 목록 (Feature List)

`requirements.md`의 요구사항을 실제로 구현할 때 참고하는 체크리스트다.
각 스택을 시도할 때 본 목록을 그대로 활용하거나, 스택 특성에 맞게 일부를 치환/추가한다.

## 우선순위 표기

- **[필수]** — 모든 스택에서 반드시 구현
- **[심화]** — 시간/의욕이 될 때 도전
- **[운영]** — 운영·배포 관점에서 학습 차원

---

## 1. 핵심 CRUD [필수]

- [ ] 목록 조회: 페이징, 검색, 정렬, 카테고리/태그 필터
- [ ] 상세 조회: 조회수 증가, 이전/다음 글
- [ ] 글 작성: 에디터(마크다운/리치텍스트), 이미지 업로드, 임시저장
- [ ] 글 수정/삭제: 권한 체크(작성자/관리자), 수정 이력
- [ ] 댓글/대댓글: depth 정책, 수정/삭제

## 2. 인증/인가 [필수]

- [ ] 회원가입/로그인/로그아웃
- [ ] 세션 vs JWT vs 쿠키 방식 비교
- [ ] 비밀번호 해싱 (bcrypt 등)
- [ ] 권한 레벨: 비회원/회원/관리자
- [ ] CSRF, XSS 방어

## 3. 데이터/DB [필수]

- [ ] ERD 설계 (User, Board, Comment, File 등)
- [ ] 인덱스 전략 (검색 성능)
- [ ] N+1 문제 해결
- [ ] 트랜잭션 처리

## 4. 파일 처리 [필수]

- [ ] 업로드/다운로드, 용량 제한, 확장자 검증
- [ ] 로컬 스토리지 vs 클라우드(S3 등)
- [ ] 이미지 썸네일 생성

## 5. 심화 [심화]

- [ ] API 설계: RESTful vs GraphQL, OpenAPI 문서화
- [ ] 캐싱: Redis (조회수, 인기글, 세션)
- [ ] 검색: LIKE → Full-text → Elasticsearch 단계적 진화
- [ ] 알림: WebSocket/SSE 실시간, 이메일
- [ ] 로깅/모니터링: Logback, Sentry, Prometheus
- [ ] 테스트: 단위/통합/E2E
- [ ] CI/CD: GitHub Actions, Docker

## 6. 비기능 요건 [필수/심화 혼합]

- [ ] 페이지네이션: Offset vs Cursor
- [ ] 동시성 처리 (조회수 중복 증가 등)
- [ ] 대용량 데이터 대비 (슬로우 쿼리 분석)
- [ ] 반응형 UI / 접근성

## 7. 프로젝트 운영 [운영]

- [ ] 환경변수 관리 (.env)
- [ ] 마이그레이션 도구 (Flyway 등)
- [ ] lint/format 설정
- [ ] 실행 방법 문서화

---

## 사용 방법

1. 시도할 스택 브랜치를 만든다.
2. 본 문서를 기준으로 **해당 스택에 해당하는 항목**에 대해 구현한다.
3. 각 항목 진행 상황을 체크박스로 갱신한다.
4. 학습 중 새로운 아이디어가 생기면 본 문서에 항목을 추가하고, `requirements.md` 갱신 필요 여부를 검토한다.

> 체크 상태는 **stack-agnostic**하게 두지 말고, 가능하면 `docs/<stack-name>/features-progress.md`처럼
> 스택별 진행 파일을 만들어 본 문서를 복제/관리한다.
