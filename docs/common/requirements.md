# 요구사항 (Requirements)

게시판 프로젝트의 요구사항을 정리한다.
**학습 목표**와 **사용자/비즈니스 관점의 기능·비기능 요구사항**을 분리해 기술한다.
구체적인 구현 체크리스트는 `features.md`를 참조한다.

## 1. 프로젝트 목적

- 다양한 web 기술 스택과 도구의 **사용법·구조·흐름**을 학습한다.
- 실제 서비스에 가까운 게시판 도메인을 기준으로 여러 기술 스택을 비교/실험한다.
- 단순 TODO 앱이 아닌, 인증·권한·검색·파일·알림 등 다양한 부기능을 포함한다.

## 2. 대상 사용자 (페르소나)

| 구분 | 권한 |
| --- | --- |
| 비회원(손님) | 게시글/댓글 조회만 가능 |
| 회원 | 글·댓글 작성/수정/삭제(자기 글), 회원정보 관리 |
| 관리자 | 모든 글/댓글/회원 관리, 공지·차단 처리 |

## 3. 학습 요구사항

본 프로젝트의 학습 목표를 **학습 수준**과 **주제**로 분류한다.
이는 "무엇을 만들 것인가"가 아니라 "**무엇을 학습·경험할 것인가**"에 관한 항목이다.
세부 구현 항목은 `features.md`를 참조한다.

### 3.1 학습 수준

| 수준 | 의미 |
| --- | --- |
| **입문 [P0]** | 기본 CRUD·인증·DB 흐름을 직접 구현하고 이해한다 |
| **중급 [P1]** | 인덱스·트랜잭션·캐싱·테스트 등 운영 관점을 다룬다 |
| **심화 [P2]** | 단계적 진화·실시간·모니터링·CI/CD 등 심화 주제를 다룬다 |

### 3.2 주제별 학습 목표

| 주제 | 입문 [P0] | 중급 [P1] | 심화 [P2] |
| --- | --- | --- | --- |
| 인증 | 세션 기반 로그인, 비밀번호 해싱, 권한 검증 | 세션 vs JWT 흐름 비교, 토큰 발급·갱신 | OAuth/SSO, refresh token rotation |
| DB | ERD 설계, 기본 CRUD | 인덱스 전략, N+1, 트랜잭션 | 샤딩, 레플리케이션 |
| 검색 | LIKE 검색 | Full-text 인덱스 | LIKE → Full-text → ES 단계적 진화 |
| 캐싱 | - | Redis 조회수·인기글 캐싱 | 캐시 무효화 전략, cache stampede |
| 파일 | 업로드/다운로드, 확장자·용량 검증 | 이미지 썸네일, 클라우드 스토리지(S3 등) | CDN, 비동기 처리 |
| 알림 | - | 이메일 알림 | WebSocket/SSE 실시간 |
| 테스트 | - | 단위 테스트 | 통합/E2E 테스트 |
| 배포/운영 | 환경변수 분리 | 마이그레이션, 실행 방법 문서화 | 로깅/모니터링, CI/CD |

> P0/P1/P2는 우선순위이며, 시도할 스택의 깊이에 따라 조정한다.

## 4. 기능적 요구사항

### 4.1 게시글
- 사용자는 글을 작성/수정/삭제할 수 있다.
- 작성자는 본인 글에 한해 수정·삭제 권한을 갖는다.
- 비회원도 게시글과 댓글을 **조회**할 수 있다.
- 글 상세 조회 시 조회수가 증가한다.
- 사용자는 댓글을 달고, 대댓글을 통해 토론을 이어갈 수 있다.

### 4.2 회원
- 회원가입/로그인/로그아웃이 가능해야 한다.
- 비밀번호는 안전하게 저장되어야 한다(평문 금지).
- 로그인·로그아웃 흐름이 정상 동작해야 한다.

### 4.3 검색·탐색
- 제목/본문/작성자 기준 **검색**이 가능해야 한다.
- 카테고리·태그로 분류해 **필터링**할 수 있어야 한다.
- 정렬(최신/조회수/추천 등)을 지원해야 한다.

### 4.4 파일
- 게시글에 이미지를 첨부할 수 있어야 한다.
- 업로드된 파일은 다운로드할 수 있어야 한다.

### 4.5 관리(관리자)
- 부적절한 글/댓글/회원을 관리(삭제·차단)할 수 있다.
- 공지사항(상단 고정)을 작성할 수 있다.

## 5. 비기능적 요구사항

### 5.1 보안
- 비밀번호는 해시 처리하여 저장한다.
- CSRF, XSS, SQL Injection 등 기본 공격에 대한 방어가 필요하다.
- 권한 검증을 통해 인가되지 않은 접근을 차단한다.

### 5.2 성능
- 페이징·인덱싱을 통해 대량 데이터에서도 응답 지연이 크지 않아야 한다.
- 조회수·인기글 등 read-heavy 경로는 캐싱을 고려한다.

### 5.3 사용성
- 주요 페이지는 데스크톱·모바일 모두에서 자연스럽게 동작해야 한다(반응형).
- 기본적인 웹 접근성(키보드 탐색, 명도 대비 등)을 고려한다.

### 5.4 운영
- 환경 변수, 마이그레이션, 로깅 등 **운영 관점** 요소를 학습 범위에 포함한다.
- 실행 방법(설치·빌드·기동)을 README 또는 docs에 명시한다.

## 6. 제약 및 가정

- **학습 목적**이므로 상용 수준의 SLA·SLO는 요구하지 않는다.
- 같은 기능을 여러 스택으로 **여러 번** 구현할 수 있다(비교 학습).
- 트래픽/규모는 학습 가능한 범위(예: 소규모 동시 사용자)를 가정한다.
